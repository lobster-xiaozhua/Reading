# C 端开发计划

> **版本**：V1.0.0 · 2026.07
> **依据**：《01-前端底层设计》《02-通用设计》《03-C端专项设计》
> **目标产品**：小说阅读 Web 站 + H5 移动端 + 桌面端阅读器
> **维护方**：C 端前端工程组

---

## 0. 计划定位

本文档将三份设计规范转化为**可执行的开发计划**，明确阶段、任务、依赖、交付物与验收标准，作为 C 端从零到一上线的工程蓝图。

**关键约束**：
- 严格遵循三层 Token 架构（L1 Primitive → L2 Semantic → L3 Component），组件代码禁止裸色值，CI 拦截违规实现。
- 三端（Web / H5 / 桌面端）共用同一套令牌与组件，通过响应式断点与端差异策略适配，H5 不做功能降级。
- 阅读器是 C 端灵魂，性能与沉浸感优先级最高（LCP < 1.5s，章节切换 < 300ms）。

```
P0 → P1 → P2 ┬→ P3 → P4 → P5(核心页面) → P6(扩展) → P8 → P9
```

**强制依赖**：
- P1 是所有后续阶段的前置，令牌不就绪禁止开发组件。
- P3 依赖 P2（BookCard 依赖 Button/Tag，ChapterList 依赖 Skeleton）。

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 令牌体系返工（设计改版） | 全组件连锁修改 | P1 阶段冻结令牌版本，P0-5 Figma 同步管线保证单一真值 |
| 阅读器性能不达标（章节切换 > 300ms） | 核心体验劣化 | P4-8 预加载 + LRU + 性能埋点先行，越早暴露越好 |
| 三端组件复用率低 | 重复开发 | P2 通用层强制共享，CI 校验禁止 apps 内直接实现通用组件 |
| H5 弱网首屏崩 | 流失核心场景 | P7-5 首屏优化 + P7-8 弱网降级 + Service Worker 兜底 |
| 暗色/阅读主题色彩流动干扰 | 阅读不适 | 主题切换强制 dur-instant 90ms，CI 禁止阅读器内 > 90ms 主题过渡 |
| 图标色值硬编码 | 主题不跟随 | token-scanner 强制 SVG 内无 fill/stroke 色值 |
| VIP/打赏支付链路 | 资金安全 | P6-3/P6-7 与后端联调，前端只做 UI，支付凭证由后端校验 |
