## 二、规划原则

- **先稳后进**：P0 阶段补齐生产级基础设施（迁移、CI 门禁、可观测性），再叠加业务。
- **端到端闭环**：每个功能方向同时覆盖 C 端体验、B 端运营、后端支撑三个层次。
- **复用共享包**：新增能力优先沉淀进 `@novel/components` / `@novel/types`，保持 C/B 端一致。
- **可度量验收**：每个优化项给出量化目标（性能指标、覆盖率、转化率）。

## 三、阶段规划

### P0 — 基础加固期（0–2 个月）｜工程质量优先

| 方向 | 事项 | 验收标准 |
|------|------|----------|
| 数据库迁移 | 引入 Alembic，`create_all` 仅限测试环境 | 生产库可执行 `alembic upgrade head` 平滑演进 |
| 搜索基础设施 | 接入 Elasticsearch：作品/章节索引、搜索与建议接口切换 | 搜索 P95 < 200ms，中文分词正确率达标（当前环境无 ES 服务，先产出索引方案，代码接入待有环境后落地） |
| 前端质量门禁 | 共享包（tokens/icons/types/components/b-end/tools）补齐真实 ESLint，替换占位符 | CI 全量 lint 通过，零 error |
| 后端质量 | 服务层测试补齐，覆盖率 87% → 90%+ | `pytest --cov` 达标且 CI 门禁生效 |
| 可观测性 | RUM 落库 + 结构化日志 + 请求指标（当前环境无 Sentry，链路用已有 traceId） | 前后端错误可查询、告警可达 |
| 部署容器化 | Dockerfile + docker-compose（MySQL/Redis/ES/后端/前端） | 一键 `docker compose up` 启动全栈（当前环境无 docker，产出配置待验证） |
| 巡检增强 | 巡检脚本支持定时执行（cron 包装），失败自动告警 | 巡检报告每日产出，失败有通知 |

### P1 — 产品体验期（2–6 个月）｜阅读体验与商业化

> 支付相关（支付闭环、订阅管理）暂缓，排期后置。

| 方向 | 事项 | 验收标准 |
|------|------|----------|
| 移动端 | C 端响应式适配（375px 起），阅读器移动端手势优化 | 核心页面 375px 无横向滚动，阅读器移动可用 |
| 离线阅读 | 阅读器章节预取 + Service Worker 离线缓存 + PWA | 弱网下已缓存章节可完整阅读 |
| 阅读体验 | 字号/行距/背景调节、夜间护眼模式、翻页动画、阅读进度记忆强化 | 设置即时生效并持久化，体验评分提升 |
| 搜索增强 | 搜索词纠错、拼音支持、热搜榜权重算法、结果高亮 | 搜索零结果率下降 30% |
| 推荐升级 | 基于阅读行为的协同过滤 + 新书冷启动 + 推荐解释 | 推荐位点击率提升 20% |
| 内容缓存 | Redis 缓存热榜/详情/章节，章节内容静态化 + CDN | 详情页/阅读页 P95 < 150ms |

### P2 — 生态扩展期（6–12 个月）｜社区与创作者经济

| 方向 | 事项 | 验收标准 |
|------|------|----------|
| 社区 | 话题、书单从"展示"升级为完整社区：发帖、关注、评论互动、内容审核 | 社区 DAU 达目标 |
| 作者端 | 作者入驻、作家专区、创作后台（上传/存稿/发布）、稿费自助提现 | 作者自助完成签约→发布→提现 |
| 内容运营 | 运营活动管理（限免、签到、任务）、Push 推送、站内信 | 活动配置化上线，无需发版 |
| 数据分析 | 实时阅读漏斗、作品转化、AB 实验平台、用户画像 | 数据看板 T+1 可用，AB 实验可闭环 |
| AI 能力 | AI 辅助审核（敏感内容初审）、智能摘要/书评、语义搜索 | 审核效率提升 50% |
| 国际化 | 内容多语言、币种、时区适配 | 支持多语言站点配置 |

## 四、分方向优化清单（跨阶段）

### 4.1 工程质量

- [ ] **真实 lint 门禁**：前端 `eslint` 由占位符改为 `eslint-plugin-react` + `hooks` + `typescript-eslint`，接入 `pnpm run ci`。
- [ ] **Alembic 迁移**：模型变更走迁移文件，去除开发 `create_all`，测试环境保留 seed 逻辑。
- [ ] **测试金字塔**：优先补 services/repositories 单测，E2E 用现有 Playwright 巡检扩展关键链路。
- [ ] **CI 缓存与并行**：pnpm 缓存、pytest 分片、typecheck 与 lint 并行，CI 总时长压到 5 分钟内。
- [ ] **依赖治理**：`pnpm audit` / `pip-audit` 纳入 CI 门禁，废弃依赖定期清理。
- [ ] **Storybook 覆盖**：新组件强制补充 Story + a11y 检查。

### 4.2 C 端产品

- [ ] **移动端适配**：核心页面（发现/详情/阅读/书架）移动优先。
- [ ] **阅读器增强**：主题、字号、字体、翻页模式、划线、词典、夜间模式。
- [ ] **离线与 PWA**：章节缓存、Service Worker、安装引导。
- [ ] **个性化**：推荐流、猜你喜欢、新书提醒、追更通知。
- [ ] **社区互动**：书评长文、话题讨论、书单收藏、作者关注。
- [ ] **无障碍**：WCAG 2.1 AA，配合 a11y Storybook 检查。
- [ ] **性能**：首页聚合接口拆流式加载、图片懒加载、骨架屏、路由预加载。

### 4.3 B 端产品

- [ ] **审核工作台**：批量审核、敏感词高亮定位、审核规则配置化、AI 初审。
- [ ] **运营工具**：活动/任务/签到配置、Push 与站内信模板、公告管理。
- [ ] **数据看板**：实时 KPI、阅读漏斗、留存分析、作者收益报表。
- [ ] **权限细化**：数据级权限（按分类/作者划分数据范围）、操作审计日志。
- [ ] **导入导出**：作品/章节批量导入、Excel 导出、批量替换。

### 4.4 技术架构

- [ ] **搜索**：ES 双写索引、平滑切换、索引重建任务。
- [ ] **消息队列**：Kafka/RabbitMQ 支撑异步任务（热搜统计、推荐更新、通知发送、字数汇总）。
- [ ] **缓存分层**：Redis 热榜/详情缓存 + 本地热点缓存 + CDN 静态章节，含缓存一致性方案。
- [ ] **限流与安全**：按 IP/用户维度限流策略完善、CSRF、CSP 安全头、上传文件类型校验。
- [ ] **数据量演进**：章节内容分表/冷热分离、历史数据归档。
- [ ] **部署**：容器化 + CI/CD 流水线（构建→测试→发布），支持灰度。

### 4.5 商业化

- [ ] **VIP 体系**：套餐、权益、订单、支付回调、到期续费、退款对账。
- [ ] **打赏/月票**：从模拟升级为真实支付与分成结算。
- [ ] **作者经济**：稿酬计算（买断/分成）、提现流程、税务留档。
- [ ] **增长工具**：邀请码、新人礼包、签到打卡、裂变分享卡片。

## 五、优先级建议

| 优先级 | 方向 | 理由 |
|--------|------|------|
| P0 | Alembic 迁移 | 生产上线的前置条件，无迁移不可上生产 |
| P0 | ES 搜索落地 | 架构已规划 ES，现有 SQL 搜索是规模瓶颈 |
| P0 | 前端 lint + 覆盖率门禁 | 保障后续迭代质量，避免技术债累积 |
| P0 | 容器化部署 | 统一环境，支撑后续所有功能联调 |
| P1 | 移动端 + 离线阅读 | 阅读产品的核心体验场景 |
| P1 | 阅读体验 + 搜索增强 | 直接影响留存与转化 |
| P1 | 推荐 + 缓存 | 直接影响留存与性能 |
| 后置 | 支付闭环 | 暂缓，待商业模式与合规就绪后启动 |
| P2 | 社区 + 作者端 + AI | 生态型扩展，依赖前两期数据积累 |

## 六、风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| ES 部署与运维成本 | P0 搜索切换延期 | 先 docker-compose 单节点，数据量达标后再上集群 |
| 支付合规与审核 | P1 商业化延期 | 优先对接聚合支付沙箱，流程先跑通再上正式商户号 |
| 移动端改造工作量 | P1 体验目标达成滞后 | 按页面优先级迭代，先保证核心阅读链路 |
| AI 能力依赖外部模型 | P2 依赖第三方 | 接口抽象化，预留自建/第三方切换 |
| 数据迁移丢失 | 上线风险 | 全量迁移脚本 + 回滚策略 + 巡检验证 |

## 七、落地节奏

1. **当月**：启动 P0，优先 Alembic 迁移 + 前端 lint 门禁 + 容器化。
2. **每双周**：`pnpm run validate` + Playwright 巡检回归，保证不引入回归。
3. **每季度**：复盘 P0/P1 验收标准，调整 P2 排期。
4. **全周期**：新增能力遵守"功能 → 测试 → 文档 → 巡检"四步闭环，文档同步更新至本目录。
