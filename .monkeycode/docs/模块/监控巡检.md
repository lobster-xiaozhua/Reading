# 监控巡检

## 概述

基于 Playwright 的智能巡检系统，覆盖后端健康检查、API 接口、前端页面渲染和业务链路。API 接口列表见 [INTERFACES.md](../INTERFACES.md)。

- 框架: Playwright 1.62
- 测试位置: `monitoring/checks/`
- 配置文件: `monitoring/playwright.config.ts`
- 检查总数: 41 项

## 运行时指标（/metrics）

进程内指标端点 `/metrics`（Prometheus 文本格式）提供三层可观测性：

- **HTTP 请求**：按路径计数/耗时分桶/5xx 错误数（由 AccessLogMiddleware 写入）
- **Redis 缓存命中率**：`redis_cache_hits_total` / `redis_cache_misses_total` /
  `redis_cache_hit_rate`（由 `utils/cache.cache_get` 打点，覆盖书籍详情、章节列表、
  章节正文、评分分布、发现页聚合等核心读取）
- **缓存热 key 分析**：`redis_cache_pattern_hits_total{pattern=...}` /
  `redis_cache_pattern_misses_total{pattern=...}`（缓存键中的数字 ID 归一化为
  `{id}` 聚合为模式，可识别高访问量与低命中率的缓存模式）
- **Redis 命令延迟**：`redis_command_calls_total{command=...}` /
  `redis_slow_command_calls_total{command=...}`（`get_redis` 返回 `_TimedRedis`
  包装客户端，顶层 async 命令按耗时记录，超过 `REDIS_SLOW_COMMAND_THRESHOLD_MS`
  （默认 20ms）的慢命令保留 Top 50 明细；pipeline 等复合方法不逐命令包装）
- **DB 慢查询**：`db_slow_queries_total` / `db_slow_query_avg_ms`（SQLAlchemy
  `before/after_cursor_execute` 事件监听，超过 `SLOW_QUERY_THRESHOLD_MS`（默认 100ms）
  的单条 SQL 记日志并计数）；`db_slow_query_top_ms{statement=...}` 暴露最慢的
  50 条 SQL 明细（语句已归一化：字符串/数字替换为 `?`，按耗时降序），运维无需
  翻日志即可定位最慢 SQL

生产环境访问 `/metrics` 需携带有效 access token。

## 配置

```typescript
// playwright.config.ts 核心配置
{
  timeout: 30000,        // 每个测试超时 30s
  retries: 1,            // 失败重试 1 次
  workers: 1,            // 单 worker 顺序执行
  reporter: ['list', ['json', { outputFile: 'results.json' }]],
  // 6 个 Playwright 项目
  projects: ['backend', 'api-b-end', 'api-c-end', 'pages-b-end', 'pages-c-end', 'business-flow'],
}
```

## 运行方式

```bash
# 全量 41 项检查
pnpm run monitor

# 分类运行
pnpm run monitor:health    # 仅健康检查
pnpm run monitor:api       # 仅 API 接口巡检
pnpm run monitor:page      # 仅前端页面渲染巡检
pnpm run monitor:flow      # 仅业务链路巡检

# 手动运行（带参数）
bash monitoring/run.sh --only health
bash monitoring/run.sh --report json
```

## 运行脚本

`monitoring/run.sh` 在启动测试前自动检查：

- 后端服务（端口 8000）是否存活
- B 端管理后台（端口 5174）是否存活
- C 端 Web（端口 5173）是否存活
- 输出报告到 `monitoring/reports/` 目录
