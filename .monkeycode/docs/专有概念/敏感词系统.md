# 敏感词系统

采用 DFA Trie 算法实现 O(n) 时间复杂度的敏感词扫描，配合三级过滤策略确保内容安全。审核流程中的集成见 [作品状态流转](./作品状态流转.md)。

## 技术实现

### DFA Trie

文件: `backend/app/utils/sensitive_trie.py`

确定性有限自动机（DFA）前缀树，具备以下特性：

- **构建**: 将敏感词库构建为 Trie 树，每个节点存储字符和子节点映射
- **扫描**: O(n) 时间复杂度，n 为文本长度
- **匹配模式**:
  - 最长匹配：优先匹配最长的敏感词（如 "钓鱼" 和 "钓鱼网站" 同时命中时取后者）
  - 重叠匹配：支持重叠敏感词的检测
- **位置标记**: 返回所有命中词及其在文本中的起止位置

### 敏感词库

文件: `backend/app/models/audit.py` — `SensitiveWord` 模型

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 自增主键 |
| text | str | 敏感词文本 |
| level | int | 敏感级别（1/2/3） |
| suggestion | str | 处理建议 |
| lib_version | str | 库版本（唯一约束: text+level） |

### B 端管理接口

| 接口 | 说明 |
|------|------|
| `GET /sensitive-words` | 获取敏感词库（分页） |
| `POST /sensitive-words` | 添加敏感词 |
| `POST /sensitive-words/check` | 扫描文本 |
| `DELETE /sensitive-words` | 删除敏感词 |

## 三级过滤策略

| 级别 | 标签 | 策略 | 说明 |
|------|------|------|------|
| L1 | 高风险 | `block` | 自动阻止保存/发布，提示用户修改 |
| L2 | 中风险 | `require-audit` | 标记为需要人工审核 |
| L3 | 低风险 | `monitor` | 仅记录日志，不阻断操作 |

### 前端过滤策略

文件: `packages/b-end/src/data-model/sensitive-filter.ts`

B 端前端组件集成见 [模块/设计系统.md](../模块/设计系统.md) 的 ChapterEditor 章节。

```typescript
export function scanText(text: string, lib: SensitiveWordLib): ScanResult {
  // 返回命中的敏感词列表及级别
}

export function shouldBlockSave(result: ScanResult): boolean {
  // 存在 L1 敏感词时阻止保存
  return result.hits.some(h => h.level === 1);
}

export function hasRequireAudit(result: ScanResult): boolean {
  // 存在 L2 敏感词时标记为需审核
  return result.hits.some(h => h.level === 2 || h.level === 1);
}
```

## 集成场景

### 章节编辑器中的实时扫描

ChaperEditor 组件内置敏感词检测：

1. 用户输入时实时扫描
2. L1 敏感词用红色波浪线标记
3. L2 敏感词用黄色波浪线标记
4. 状态栏显示敏感词统计

### 审核流程中的扫描

1. 提交审核时自动触发全量扫描
2. 扫描结果记录在审核记录的 `sensitive_hits` 字段
3. 审核员在审核界面查看命中详情

### 内容发布前的扫描

1. 作品/章节保存时自动扫描
2. L1 命中阻止保存操作
3. 命中记录写入审计日志
