# 作品状态流转

作品管理是 B 端运营的核心流程，涉及创建、审核、上架、下架的完整生命周期。状态转换由 [状态机](./状态机.md) 统一管理。

## 完整生命周期

```
作者创建草稿
    │
    ▼
[草稿] ────提交审核────→ [待审核] ────审核通过────→ [已发布]
                                         │
                                         │ 上架操作
                                         │
                                         ▼
                                      [已上架] ←── 重新上架 ──→ [已下架]
                                         │
                                         │ 下架操作
                                         │
                                         ▼
                                      [已下架]
```

## B 端状态

| 状态 | 说明 | 操作 |
|------|------|------|
| `draft` | 草稿，仅作者可见 | 编辑、提交审核 |
| `pending` | 待审核，审核员可见 | 审核通过/驳回 |
| `published` | 已发布，读者可见 | 下架 |
| `offline` | 已下架，读者不可见 | 重新上架、编辑 |

## C 端状态

C 端读者只关注是否完结：

| 状态 | 说明 |
|------|------|
| `ongoing` | 连载中 |
| `completed` | 已完结 |

## 审核流程

```
提交审核 → 敏感词扫描 → 审核队列 → 审核员处理
                                        ↓
                          ┌── 通过 ──→ 标记为待上架
                          │
                          └── 驳回 ──→ 退回草稿
```

审核流程集成 [敏感词系统](./敏感词系统.md) 的三级过滤策略，自动阻断或标记含敏感词的内容。

### 审核级别

| 级别 | 说明 |
|------|------|
| L1 | 自动通过（无敏感词命中） |
| L2 | 需要人工审核（命中中等敏感词） |
| L3 | 自动驳回（命中高危敏感词） |

## 章节状态流转

章节独立于作品拥有自己的状态机，但受作品整体状态约束：

- 作品为 `draft` 时，章节不可发布
- 作品为 `offline` 时，章节对读者不可见
- 章节状态流转与作品类似: `draft → pending → published → offline → published`

## 运营操作

| 操作 | 说明 | 前置条件 |
|------|------|----------|
| 提交审核 | 将作品/章节提交到审核队列 | 状态为 `draft` |
| 审核通过 | 审核通过并上架 | 状态为 `pending` |
| 审核驳回 | 退回草稿，需填写驳回原因 | 状态为 `pending` |
| 上架 | 已发布作品正式上架 | 状态为 `published` |
| 下架 | 下架作品，需填写下架原因和备注 | 状态为 `published` |
| 重新上架 | 下架作品重新上架 | 状态为 `offline` |

## 批量操作

B 端支持批量状态变更：

```json
{
  "action": "shelve",  // shelve | unshelve | approve | reject | delete
  "ids": [1, 2, 3],
  "reason": "批量操作原因"
}
```
