## 问题清单与修复方案

### P0 - 阻塞性问题

#### 1. 后端 Error Handler 将 404 转为 500

**文件**: `backend/app/middlewares/error_handler.py:76`

**问题**: 未注册 `HTTPException` 处理器，通配 `Exception` 处理器捕获所有 404 请求并返回 HTTP 500。

**影响**: 不存在的路由路径返回 500 而非 404，前端无法区分"接口不存在"和"服务异常"。

**修复**: 在 `register_exception_handlers` 中增加 `HTTPException` 专用处理器，返回正确状态码。

#### 2. start.sh 启动脚本错误

**文件**: `start.sh:14`

**问题**: `trap` 命令格式错误，参数未加引号且缺少 `kill` 命令。

```
# 当前
trap "$BACKEND_PID $ADMIN_PID $WEB_PID" EXIT
# 正确
trap "kill $BACKEND_PID $ADMIN_PID $WEB_PID" EXIT
```

**影响**: 脚本退出时无法正确清理后台进程。

#### 3. 阅读进度上报字段名不匹配

**文件**: 
- 前端: `apps/web/src/api/fetcher.ts` (camelCase: `chapterId`, `chapterIndex`)
- 后端: `backend/app/api/c_end/interaction.py` (snake_case: `chapter_id`, `chapter_index`)

**问题**: FastAPI 默认不做 case 转换，前端发送的 camelCase 字段与后端 Pydantic 模型的 snake_case 字段不匹配，导致 `chapter_id` 和 `chapter_index` 始终为 `None`。

**修复**: 统一为 snake_case（前端发送时转换字段名），或使用 FastAPI 的 `alias` 机制。

---

### P1 - 功能性缺失

#### 4. B端工作台使用 Mock 数据

**文件**: `apps/admin/src/pages/WorkbenchPage.tsx`

**问题**: KPI 卡片和内容概览数据使用 `setTimeout` 设置硬编码 mock 数据，后端 `/workbench/kpi` 和 `/workbench/word-trend` 端点存在但未被前端调用。

**影响**: 工作台永远显示静态假数据，无法反映真实业务情况。

**修复**: 移除 mock 数据，调用 `fetcher.workbench.getKpiCards()` 和 `fetcher.workbench.getWordCountTrend()` 获取真实后端数据。

#### 5. B端图表数据全部使用 Mock

**文件**: `apps/admin/src/api/chart-api.ts`

**问题**: 所有图表数据（趋势图、字数增长、热力图等）在客户端生成随机数据，后端端点存在但未被使用。

**影响**: 数据看板中的图表全部为假数据。

**修复**: 将图表数据获取切换到后端 API，移除客户端随机数据生成逻辑。

#### 6. C端 HTTP 客户端无鉴权机制

**文件**: `apps/web/src/api/http.ts`

**问题**: HTTP 客户端没有任何 token 注入或 cookie 处理逻辑。后端 `get_current_reader` 依赖虽提供了 demo 降级机制，但读者登录/注册流程完全缺失。

**影响**: 读者无法登录，个人中心、书架、阅读历史、互动操作等功能无法正常使用。

**修复**: 
- 实现读者登录/注册页面
- 在 HTTP 客户端中注入 Authorization header
- 实现 token 持久化（localStorage）

#### 7. 数据库种子数据不完整

**问题**: 种子脚本 (`scripts/seed.py`) 未生成以下数据：
- Banners（横幅广告）
- Tags（标签）
- Readers（读者）和读书相关数据
- Comments（评论）和 Reviews（书评）
- Bookshelves（书架）数据
- Reading histories（阅读历史）

**影响**: 前端页面加载后大量显示空状态，无法展示完整业务流程。

**修复**: 扩展 seed 脚本，生成完整的演示数据。

### P2 - 体验优化

#### 8. 缺少 `.env.example` 配置文件模板

**问题**: 后端配置通过 `pydantic-settings` 从 `.env` 读取，但仓库中没有 `.env.example` 模板文件，新开发者无法知道需要配置哪些环境变量。

**修复**: 创建 `.env.example` 包含所有必需配置项及注释。

#### 9. Storybook 组件库不完整

**问题**: Storybook 配置存在但只有 1 个 story（AntDTokenBridge），组件库的 80+ 个组件缺乏 story 文档。

**影响**: 无法通过 Storybook 预览和测试组件。

**修复**: 为关键组件添加 story 文档。

#### 10. 分类页 Tag 过滤为客户端二次过滤

**文件**: `apps/web/src/api/fetcher.ts`

**问题**: 当指定 tags 时，先拉取 100 条数据后在浏览器端过滤，数据量超过 100 时结果不完整。

**修复**: 后端 `/books` 端点增加 tag 过滤参数支持。

## 关键技术决策

1. **C端鉴权方案**: 使用 JWT token + localStorage 持久化，与 B 端方案一致。后端 `get_current_reader` 已支持 demo 模式降级，先实现最小登录流程，后续可扩展 OAuth/第三方登录。

2. **工作台数据方案**: 后端 `/workbench/kpi` 和 `/workbench/word-trend` 端点的返回数据格式与前端模板已对齐，直接对接即可。

3. **种子数据策略**: 幂等写入（已存在不重复），扩展 banners、tags、readers、comments 等表，确保前端所有页面都有可展示数据。
